# Outbound-host allowlist (#436).
#
# Every `https://<host>` literal that scripts/egress-inventory.sh finds in the
# shipped source must appear here with a line saying what it is. The gate is
# `bash scripts/egress-inventory.sh --check`; CI runs it, so a new destination
# cannot land undocumented.
#
# Being on this list is NOT permission to call out. It only records that
# somebody looked. The operator-facing answer — what is called, why, and which
# switch turns it off — is the egress table in SELF_HOSTING.md
# («Профиль доставки и исходящий трафик»), and the personal-data consequences are in
# docs/compliance/data-map.md.
#
# Three kinds of entry, marked in the comment:
#   [call]    the product opens this connection itself
#   [link]    a URL the product renders for a human to click, or a browser asset
#   [text]    a documentation URL in a comment, error message or lockfile —
#             nothing connects to it at runtime
#
# A line prefixed with `~` is a destination that does NOT appear as a literal in
# this repository — it is reached from inside a dependency — so the scan cannot
# find it and the diff must ignore it. Those entries exist because the gate is
# only as honest as its blind spots: a destination that moves into an SDK does
# not stop being a destination. Add one whenever an outbound call's host is
# chosen by a library rather than by our source.
