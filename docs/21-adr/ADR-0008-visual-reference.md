# ADR-0008: Визуальный референс — Atlassian Design System и Fluent 2, своя гамма

Дата: 28 сентября 2026 года
Статус: Accepted

## Контекст

ADR-0007 задал числовые правила (контраст, сетка, шкала, токены), но не отвечает, как интерфейс должен выглядеть в целом: плотность, пропорции, поверхности, характер компонентов. Владелец назвал ориентиры: Claude Desktop, Atlassian, Microsoft Office — с другой гаммой и адаптацией под продукт.

## Рассмотренные варианты

- Claude Desktop как основа — спокойный, много воздуха / дизайн проприетарный, код и ассеты брать нельзя, продукт другого класса (чат, не трекер);
- Atlassian Design System (ADS) — домен совпадает (задачи, проекты, доски), токены, отступы, типографика и паттерны навигации задокументированы публично, Atlaskit под Apache-2.0 / визуально узнаваем, нужна своя гамма;
- Microsoft Fluent 2 — сильные плотные таблицы, формы, командные панели, Fluent UI под MIT / стиль Office для трекера тяжеловат;
- Собственный язык с нуля — уникально / противоречит ADR-0005 (не писать GUI с нуля).

## Решение

Основной референс — Atlassian Design System: сетка 8px, шкала типографики, плотность списков и карточек, структура страницы (заголовок, действия справа, фильтры под заголовком), боковая навигация, пустые состояния, формы. Второй референс — Fluent 2 для плотных таблиц, командной панели над таблицей, диалогов и админских экранов. Claude Desktop — только настроение: тёплые нейтральные поверхности вместо чисто-серых, минимум рамок, разделение областей фоном, а не линиями, скругление 8–12px, спокойные тени.

Не копируется: гамма (остаётся «Речная синь» из ADR-0001), шрифты (Unbounded, Manrope, JetBrains Mono), логотипы и иконки брендов, тексты. Код берётся только из открытых пакетов с MIT/Apache-2.0 лицензией по ADR-0005, с записью в THIRD_PARTY_NOTICES.

Порядок работ: T-034 (аудит по ADR-0007) даёт чек-лист приёмки; T-035 перестраивает токены и базовые компоненты в `packages/ui` по референсу, затем экраны по зонам; каждая правка должна улучшать число из ADR-0007 и соответствовать паттерну из ADS или Fluent с ссылкой.

## Последствия

Положительные: у визуала появляется цельный образец, а не набор правил; спор «красиво / некрасиво» решается ссылкой на паттерн.
Отрицательные: часть компонентов 1.1–1.2 (рельса, строка задачи, карточка) перерисовывается второй раз за месяц; визуальные эталоны `e2e/visual` перезаписываются.
Что станет сигналом пересмотреть решение: если после T-035 интерфейс станет визуально неотличим от Jira или Office, усилить собственную гамму и пропорции, а не менять референс.
