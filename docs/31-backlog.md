## Эпик E8. Перепись бэкенда в чистой комнате (условие запуска — ADR-0004)

Цель: `server/` и `packages/core` перестают быть производными от Multica; аудит кода не находит совпадений. Метод clean-room: автор спецификации описывает поведение по наблюдаемому API и тестам, реализатор пишет код по спецификации, не открывая исходники Multica и текущий `server/`. Один человек не может быть обоими; в соло — спецификацию пишет агент А по контракту API, реализует агент Б с закрытым доступом к старому коду, ревью делает человек. Оценка суммарно 45–60 дней работы, ведётся в отдельном модуле `server2/` до паритета, затем переключение.
