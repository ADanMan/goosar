# Визуал и продуктовая поверхность Goosar, отличные от Multica

Актуальность исследования: 25 сентября 2026 года.

## 1. Основной вывод

Различие достигается заменой четырёх слоёв поверх неизменного бэкенда: дизайн-токены, каркас навигации, состав и раскладка ключевых экранов, словарь терминов.

При этом переработка поверхности решает не всё. Она не заменяет:

- юридической независимости: код бэкенда, API и схема остаются производными от Multica и покрыты допсоглашением V2, а не «чистой комнатой»;
- аудита кода: инструменты вроде ScanOSS продолжат находить совпадения в `server/`;
- позиционирования: «конкурент» требует и другого продуктового фокуса (русскоязычная on-prem поставка, Hermes как стандартный рантайм), не только другого вида.

Рекомендуемая схема:

```text
Пользователь
   │
   ├── apps/web, apps/desktop      экраны: новая раскладка, новый словарь  ← меняем
   ├── packages/views              композиция экранов                       ← меняем
   ├── packages/ui                 примитивы и токены                       ← меняем
   ├── packages/core               сторы, API-клиент, пути                 ← не трогаем
   └── server/                     HTTP API, daemon, Postgres              ← не трогаем
```

Для первой версии (1.1.0) достаточно токенов, навигации, словаря и трёх ключевых экранов: список задач, карточка задачи, лендинг. Для полного отличия (1.2) добавляются доска, настройки, онбординг и десктоп-специфика.

## 2. Почему «сменить палитру и шрифт» недостаточно

Это уже сделано: шрифты Montserrat и Comfortaa вместо Inter, иконка гуся, русский лендинг. Результат: скриншот доски Goosar накладывается на скриншот доски Multica с точностью до положения каждого элемента. Узнаваемость продукта задаёт не цвет, а силуэт: где навигация, как выглядит карточка, что открывается первым. Пока силуэт общий, любая палитра читается как «тема для Multica».

Что даёт смена палитры: быстрый эффект на лендинге и в маркетинговых скриншотах. Чего не даёт: отличия в работе, отличия на скриншоте пользователя, аргумента в споре о самостоятельности. Применима как первый тикет, не как решение.

## 3. Варианты глубины переработки

### 3.1. Тема поверх Multica

Назначение: смена цветов, радиусов, шрифтов через `tokens.css`. Преимущества: один день, нулевой риск регрессий. Ограничения: силуэт тот же, см. раздел 2. Отвергнут как самостоятельный вариант, принят как первый шаг.

### 3.2. Переработка поверхности (принят)

Назначение: новые токены, новый каркас навигации, новая композиция трёх ключевых экранов, новый словарь. Преимущества: отличие видно на первом экране и в повседневной работе, срок 12–16 рабочих дней, бэкенд не трогается, тесты `server/` остаются зелёными. Ограничения: `packages/core` и API остаются общими, что видно в devtools и в коде.

### 3.3. Реимплементация в чистой комнате

Назначение: своя схема, свой API, свой UI-кит, бэкенд по спецификации поведения без чтения кода Multica. Преимущества: единственный вариант, при котором аудит кода не находит родства. Ограничения: месяцы работы, два независимых исполнителя (автор спецификации и реализатор), заморозка фич. Отложен; условие возврата в ADR-0004.

## 4. Структура изменений

### 4.1. Дизайн-токены

Текущая база: `packages/ui/styles/tokens.css` (oklch, hue 60 для нейтралей, brand `oklch(0.705 0.187 47.6)` оранжевый, `--radius: 0.625rem`), переопределения в `apps/web/app/custom.css`.

Новая система «Речная синь»:

```text
--brand            oklch(0.48 0.10 230)    основной, кнопки, активные элементы
--brand-foreground oklch(0.985 0.005 90)
--accent-beak      oklch(0.72 0.17 60)     единственный тёплый акцент: индикатор агента, бейдж «в работе»
--canvas           oklch(0.985 0.005 90)   тёплый белый фон, вместо серо-бежевого hue 60
--ink              oklch(0.22 0.02 250)    текст, с синим подтоном
--rail             oklch(0.26 0.03 240)    тёмная навигационная рельса (в светлой теме тоже тёмная)
--surface          oklch(1 0 0)
--surface-border   oklch(0.90 0.01 240)
--radius           0.375rem                острее, чем 0.625rem
--status-backlog   oklch(0.70 0.02 250)
--status-todo      oklch(0.55 0.08 250)
--status-doing     oklch(0.72 0.17 60)
--status-review    oklch(0.60 0.12 300)
--status-done      oklch(0.55 0.14 160)
```

Правила: тёплый акцент один и только для агентной активности; статусы кодируются полосой слева карточки и цветом точки, не цветным фоном бейджа; тёмная тема строится инверсией `--canvas`/`--ink` с той же рельсой.

Шрифты: тело Manrope (Google Fonts, OFL), заголовки Unbounded (Google Fonts, OFL), моно JetBrains Mono. Montserrat и Comfortaa убираются: Comfortaa округлый и слишком «игрушечный» для on-prem, Montserrat визуально близок к Inter в наборе.

Документация Tailwind v4 по темам и токенам:  
https://tailwindcss.com/docs/theme

Шрифты в Next.js (self-host через `next/font/google`):  
https://nextjs.org/docs/app/api-reference/components/font

### 4.2. Каркас навигации

Сейчас: левый сайдбар 240px, три группы ссылок (личное, рабочее пространство, управление), список избранного, переключатель воркспейса сверху. Один в один Multica и Linear.

Новый каркас:

```text
┌──┬──────────────────────────────────────────────────────┐
│Р │ Командная строка: поиск, «Новая задача», переключатель│
│е ├──────────────────────────────────────────────────────┤
│л │ Контекстная панель │ Рабочая область                 │
│ь │ (зависит от раздела│ (список / карточка / настройки) │
│с │  рельсы, сворачива-│                                  │
│а │  ется в 0)         │                                  │
└──┴────────────────────┴──────────────────────────────────┘
```

Рельса 56px, тёмная, только иконки с подписью при наведении. Разделы рельсы:

```text
nav.feed        Лента      (бывшие Входящие + Чат в одном потоке)
nav.tasks       Задачи     (Issues + Мои задачи как фильтр)
nav.projects    Проекты
nav.crew        Исполнители (Агенты + Отряды на одной странице, вкладками)
nav.autopilot   Автопилот
nav.settings    Настройки  (Среды выполнения, Навыки, Потребление внутри)
```

Контекстная панель 260px показывает содержимое раздела: для «Задач» — сохранённые фильтры и проекты, для «Исполнителей» — список агентов, для «Настроек» — подразделы. Список избранного переезжает в панель раздела «Задачи».

Что не делает каркас: не меняет маршруты. Пути `paths.workspace(slug).issues()` и остальные остаются, меняется только оболочка вокруг них.

### 4.3. Ключевые экраны

Список задач (`/issues`): по умолчанию список, не доска. Строка: полоса статуса слева, ключ `ГУС-12`, заголовок, исполнитель аватаром, срок. Группировка по статусу заголовками-разделителями. Доска остаётся переключателем вида.

Карточка задачи: заголовок и описание слева, лента активности агента справа сплошным потоком (сейчас вкладки). Кнопка «Передать агенту» на первом экране карточки.

Лендинг: первый экран без скриншота доски. Вместо него — живой лог агента, выполняющего задачу, в виде терминальной ленты. Скриншот интерфейса ниже, уже в новом каркасе. Секции: «Агент как исполнитель», «Свой контур», «Hermes внутри», «Установка за пять минут».

### 4.4. Словарь

Русский словарь первичен, `packages/views/locales/ru/*.json` редактируется первым, затем `en`, `zh-Hans`, `ja` переводятся с русского.

```text
issue        → задача      (task)
inbox        → лента       (feed)
my_issues    → мои задачи  (my tasks)
agents       → исполнители (crew)
squads       → отряды      (squads)
runtimes     → среды       (runtimes)
skills       → навыки      (skills)
usage        → расход      (usage)
autopilots   → автопилот   (autopilot)
```

Ключи JSON не переименовываются, меняются значения: переименование ключей тянет `packages/core` и тесты, см. ADR-0004. Ключ задачи в UI: `ГУС-12` (уже так).

## 5. Что остаётся общим с Multica

Не делает эта переработка: не меняет HTTP API (`/api/v1/...`), схему Postgres, протокол daemon, CLI-команды `goosar issue|agent|daemon`, сторы `packages/core`, формат конфигов. Любой, кто откроет `server/`, увидит происхождение. Это осознанно: обратная совместимость с существующими установками и отсутствие регрессий важнее, чем маскировка бэкенда.

## 6. Совместимость и версионирование

- Версия 1.1.0: новая поверхность, API без изменений, миграций нет, откат = откат образов.
- Локали: ключи стабильны, поэтому старые пользовательские переводы (если кто-то форкнул) не ломаются.
- Десктоп: оболочка из `packages/views`, поэтому получает каркас автоматически; специфика окна (заголовок, трей) в T-014.
- Multica продолжает развиваться; слияния из upstream после 1.1.0 в `packages/views` и `packages/ui` будут конфликтовать. Политика: upstream берётся только для `server/` и `packages/core`, фронтенд расходится навсегда.

## 8. Безопасность

Переработка не меняет модель авторизации и не добавляет новых точек ввода. Единственный новый недоверенный поток: лента агента на лендинге. Она не читает реальные данные, это статический сценарий из `apps/web/features/landing/demo-log.ts`. Запрещено подключать лендинг к живому API.

Классы риска правок:

| Уровень | Примеры | Политика |
|---|---|---|
| L0 | Токены, шрифты, тексты локалей | Правка и визуальная проверка |
| L1 | Каркас навигации, композиция экранов | Плюс `pnpm test` пакета и проверка клавиатурной навигации |
| L2 | Всё, что задевает `packages/core` или маршруты | Запрещено в этом паке; вынести в отдельный ADR |

## 9. Ограничения среды

- Лицензия Multica (Apache-2.0 плюс условия Part I) запрещает снимать бренд и хостить сервис без разрешения; разрешение дано допсоглашением V2, документ хранится у владельца и в репозиторий не попадает.
- Шрифты Manrope, Unbounded, JetBrains Mono под SIL OFL 1.1, бандлятся через `next/font`; при добавлении обновить `THIRD_PARTY_NOTICES.md` (`node scripts/third-party-notices.mjs`).
- Tailwind v4 без `tailwind.config`: токены объявляются в `@theme inline`, как сейчас.

Условия SIL OFL:  
https://openfontlicense.org/open-font-license-official-text/

## 10. Развёртывание

Ничего нового: те же образы, `make selfhost`, Helm-чарт. Версия образов `v1.1.0`. Прод обновляется по процедуре из `SELF_HOSTING.md`, откат сменой `GOOSAR_IMAGE_TAG` на `v1.0.1`.

## 11. Тестирование

Матрица и проверки в `32-test-plan.md`. Обязательный минимум перед 1.1.0: три экрана × две темы × web и desktop, клавиатурная навигация по рельсе, контраст текста не ниже 4.5:1 по WCAG 2.2.

WCAG 2.2, критерий контраста:  
https://www.w3.org/TR/WCAG22/#contrast-minimum

## 12. Референсы

- Linear: источник силуэта Multica; нужен как «анти-референс», от чего уходим.
- Plane (github.com/makeplane/plane, AGPL-3.0): пример рельсы с контекстной панелью; берём идею раскладки, код не берём из-за лицензии.
- Huly (github.com/hcengineering/platform, EPL-2.0): лента активности сплошным потоком в карточке; берём паттерн, не код.
- Tailwind UI не используется: платный, нельзя в открытый репозиторий.
