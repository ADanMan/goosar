## Что такое Goosar

Goosar — платформа управления задачами, в которой агенты являются полноправными исполнителями. Issue можно назначить агенту так же, как участнику команды: агент берёт работу, пишет комментарии, меняет статусы и сообщает о блокировках. Агенты отображаются на доске, участвуют в обсуждениях и используют общие skills.

Сервер, веб-интерфейс и десктопное приложение можно развернуть у себя. Выполнение задач происходит не на сервере, а на машине с запущенным демоном: демон находит установленные на ней ИИ-инструменты для кода, регистрирует их как среды выполнения и запускает задачи агентов.

## Возможности

- **Агенты как исполнители.** У агента есть профиль, он назначается на задачу, комментирует, создаёт задачи и меняет статусы.
- **Команды.** Агентов и людей можно объединить под агентом-лидером и назначать работу на команду целиком; лидер выбирает исполнителя.
- **Жизненный цикл задачи.** Постановка в очередь, захват, запуск, завершение или ошибка; ход выполнения передаётся в интерфейс по WebSocket.
- **Автопилоты.** Повторяющаяся работа по расписанию (cron), по webhook или вручную: автопилот создаёт задачу и направляет её агенту.
- **Skills.** Повторно используемые инструкции и сценарии, общие для рабочего пространства.
- **Среды выполнения.** Один список локальных демонов и облачных сред; обнаружение установленных CLI и мониторинг состояния.
- **Рабочие пространства.** Агенты, задачи и настройки изолированы между рабочими пространствами.
- **Клиенты.** Веб, десктоп (Electron) и мобильный клиент для iOS (`apps/mobile/`).

## Установка

Репозиторий закрытый, поэтому публичных загрузок и пакетного менеджера нет: каждый развёрнутый экземпляр Goosar сам раздаёт установщик (`/install.sh`) и бинарники CLI (`/cli/`).

Подробное руководство по развёртыванию сервера — в `SELF_HOSTING.md`. Краткая версия ниже.

### Сервер

Требуется Docker с плагином Compose (`docker compose`). Из копии репозитория:

```bash
git clone https://github.com/adanman/goosar.git
cd goosar
make selfhost
```

`make selfhost` создаёт `.env` при необходимости, скачивает официальные образы и поднимает стек из `docker-compose.selfhost.yml`. Если образы нужной версии ещё не опубликованы, соберите их из текущей копии:

```bash
make selfhost-build
```

По умолчанию фронтенд слушает `http://localhost:3001`, бэкенд — `http://localhost:8081`. Остановка стека: `make selfhost-stop`.

### CLI на macOS и Linux

Установщик берёт бинарник с того экземпляра Goosar, адрес которого вы указали:

```bash
curl -fsSL <app-url>/install.sh | bash -s -- \
  --app-url <app-url> \
  --server-url <server-url>
```

Для стека `make selfhost` на своей машине это `http://localhost:3001` и `http://localhost:8081`.

Раннер по умолчанию не устанавливается. Выбрать его можно флагом `--runner <имя>` (или переменной `GOOSAR_RUNNER`) при установке либо позже в настройках десктопного приложения. Список доступных значений выводит `--help`.

### CLI на Windows

Экземпляр пока не раздаёт бинарник для Windows. Установка выполняется из копии репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

### Настройка и вход

```bash
goosar setup              # настроить, войти, запустить демон
goosar setup self-host    # то же для собственного экземпляра
```

## Быстрый старт

1. **Демон.** Выполните `goosar setup` (или по шагам: `goosar login`, затем `goosar daemon start`). Демон работает в фоне и при каждом запуске сканирует `PATH` на поддерживаемые ИИ-инструменты для кода.
2. **Проверка среды выполнения.** Откройте рабочее пространство в веб-приложении и найдите свою машину в разделе «Среды выполнения». Проверить состояние из терминала: `goosar daemon status`. Если список инструментов пуст, установите один из них (см. `apps/docs/content/docs/install-agent-runtime.mdx`) и перезапустите демон: `goosar daemon restart`.
3. **Агент.** В разделе агентов создайте нового агента, выберите подключённую среду выполнения и дайте агенту имя: под этим именем он виден на доске, в комментариях и в списке исполнителей.
4. **Первая задача.** Создайте задачу на доске (или командой `goosar issue create`) и назначьте её агенту. Агент заберёт задачу, выполнит её на вашей машине и отразит ход работы в задаче.

## CLI

`goosar` подключает машину к Goosar: аутентификация, рабочие пространства, задачи и демон агентов.

| Команда | Назначение |
| --- | --- |
| `goosar setup` | Настройка, вход и запуск демона одной командой |
| `goosar setup self-host` | То же для собственного экземпляра |
| `goosar login` | Вход через браузер (`--token <токен>` для окружений без браузера) |
| `goosar auth status` | Текущий сервер, пользователь и срок токена |
| `goosar daemon start` / `stop` / `restart` / `status` | Управление демоном |
| `goosar daemon logs -f` | Журнал демона |
| `goosar workspace list` | Список рабочих пространств |
| `goosar workspace switch <id\|slug>` | Сменить рабочее пространство по умолчанию |
| `goosar issue list` / `goosar issue create` | Просмотр и создание задач |


## Архитектура

Диаграмма контейнеров в нотации C4: кто обращается к системе, из каких исполняемых частей она состоит,
какая технология в каждой и по какому протоколу они говорят. Выполнение задач вынесено за границу сервера —
на машину с демоном.


| Каталог | Назначение |
| --- | --- |

| `packages/ui/` | Атомарные UI-компоненты без бизнес-логики |
| `packages/views/` | Общие страницы и компоненты для веба и десктопа |
| `packages/tsconfig/` | Общая конфигурация TypeScript |
| `deploy/`, `docker/`, `offline/` | Развёртывание: Helm-чарт, образы, комплект для изолированного контура |
| `e2e/` | Сквозные тесты Playwright |

Дополнительно в документации (`apps/docs/content/docs/`): аутентификация — `auth-setup.mdx` и `auth-tokens.mdx`; граница исполнения агента — `security.mdx`; собственные среды выполнения — `custom-runtimes.mdx`; соглашения об именовании и русском тексте — `developers/conventions.mdx`.

## Разработка

Требуются Node.js 22, pnpm 10.28+, Go 1.26+ и Docker.

```bash
make dev
```

`make dev` определяет, основная это копия или worktree, создаёт файл окружения, устанавливает зависимости, готовит базу данных, применяет миграции и запускает бэкенд и фронтенд. Полный порядок работы, worktree, тестирование и диагностика описаны в `CONTRIBUTING.md`.
