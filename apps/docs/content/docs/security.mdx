Страница отвечает на один вопрос, который задаёт внешнее ИБ-ревью: **что процесс агента может достать, чего не может и кто именно это обеспечивает — Goosar, операционная система или оператор.**

## Главное, прямым текстом [#the-short-version]

**Агент исполняется с правами владельца среды выполнения.** Демон запускает CLI среды выполнения (список — в реестре `server/pkg/agent/runtimeregistry/runtimes.yaml`) обычным дочерним процессом от того же пользователя ОС, под которым запущен сам. У этого процесса есть всё, что есть у пользователя: домашний каталог, SSH-ключи, билет Kerberos, конфигурация браузера, смонтированные сетевые ресурсы, сессии `kubectl`, `docker.sock`, учётные данные провайдера. Ни Goosar, ни демон не создают вокруг него контейнер, namespace или профиль seccomp.

Кроме того, CLI провайдеров запускаются в режимах, которые отключают их собственные подтверждения: `--dangerously-skip-permissions`, `bypassPermissions`, `--yolo`, `--trust-all-tools` (`server/pkg/agent/*.go`). Это осознанное решение продукта: задача должна доводиться до конца без человека у клавиатуры. Из него следует, что **внутренние диалоги подтверждения CLI не являются границей безопасности в Goosar**.

Правило, которое нужно принять до чтения остального:

<Callout type="warning">
Изоляция исполнения — ответственность операционной системы и оператора, а не Goosar. Goosar даёт настраиваемые ограничения на *конфигурацию* запуска. Песочницы он не даёт и не обещает.
</Callout>

Любое место в документации, которое читается как обещание изоляции, — ошибка документации. Исправляйте текст, а не толкуйте его расширительно.

## Что процесс агента достаёт [#what-the-agent-can-reach]

| Ресурс | Доступ | Кто ограничивает |
|---|---|---|
| Файловая система | всё, что читает и пишет пользователь ОС, под которым работает демон | ОС (права, отдельный пользователь, песочница провайдера); Goosar — только корни запуска, см. [ниже](#launch-roots) |
| Сеть | исходящие соединения без ограничений со стороны демона | сетевой периметр заказчика; прокси и CA задаются политикой машины (`HTTP_PROXY`, `NODE_EXTRA_CA_CERTS` и т. д.) |
| Переменные окружения | окружение процесса демона плюс `custom_env` агента | Goosar: список запрещённых ключей, см. [ниже](#environment-variables) |
| Учётные данные провайдера LLM | те, что лежат в окружении и конфигурации пользователя | ОС; Goosar их не изымает |
| MCP-серверы | те, что прошли слияние конфигураций | Goosar: allowlist развёртывания, см. [ниже](#mcp) |
| API Goosar | токен задачи (`mat_`), ограниченный этой задачей | Goosar: `RequireHumanActor` на административных маршрутах |

Отдельно: **токен задачи не является человеком.** Он подставляет `X-User-ID` инициатора, поэтому на маршрутах, где важна не роль, а сам факт живого человека, стоит `RequireHumanActor`. Это выдача CLI-токена, состав участников, приглашения, конфигурация развёртывания и MCP, провижининг. Токен задачи получает на них отказ независимо от роли пользователя, чьим именем он подписан.

## Корни запуска [#launch-roots]

Это то, что демон обеспечивает сам. `GOOSAR_ALLOWED_WORKDIR_ROOTS` — список каталогов (разделитель — системный разделитель `PATH` или запятая), внутри которых может лежать рабочий каталог задачи.

- **Не задана — поведение прежнее.** Это значение по умолчанию для облака и десктопа: демон там работает на ноутбуке самого пользователя, против его собственных проектов, и allowlist был бы театром. Действует только чёрный список: корень диска, `/`, `/Users`, `/home`, домашний каталог пользователя.
- **Задана** — демон **отказывается запускать задачу**, если рабочий каталог после разрешения симлинков лежит вне всех корней. Отказ виден в задаче как `local_directory_error` с текстом, в котором названа переменная.
- Сравнение идёт по компонентам пути, а не по строковому префиксу: `/srv/projects-old` не находится внутри `/srv/projects`.
- Сравнивается **путь после разрешения симлинков** и только он. Ссылка `/srv/projects/escape -> /home/user/.ssh` буквально лежит внутри корня, поэтому принимать буквальный путь как альтернативу означало бы отдать границу обратно.
- **Fail closed при опечатке.** Корень, который не резолвится на этой машине, не попадает в множество разрешённых; если не резолвится ни один — отказывается всё. Переменная никогда не «раскрывается обратно в любой каталог».

Чего это НЕ даёт. Агент, уже запущенный внутри корня, по-прежнему может писать куда угодно, куда может писать пользователь ОС. Отказ здесь касается *конфигурации запуска*: неверно заданный `local_directory` в проекте, ресурс, подсунутый через API, ошибка оператора. Против намеренного выхода агента за пределы каталога работает только ОС.

Код: `server/internal/daemon/local_directory.go`, `checkConfinementRoots`.

## Переменные окружения [#environment-variables]

Дочерний процесс наследует окружение демона, и поверх него накладывается `custom_env` агента. `custom_env` — это **конфигурация**, а в рабочем пространстве, где агента может править не только владелец машины, она доступна и другому человеку. Поэтому часть ключей нельзя переопределять (`isBlockedEnvKey`, `server/internal/daemon/daemon.go`):

| Семейство | Ключи | Почему |
|---|---|---|
| Внутренние | `GOOSAR_*` | конфигурация демона |
| Системные пути | `HOME`, `PATH`, `USER`, `SHELL`, `TERM`, `TMPDIR`, `TMP`, `TEMP` | подмена корня работы и разрешения бинарников |
| Конфигурации сред выполнения | `CODEX_HOME`, `CURSOR_DATA_DIR`, `CURSOR_MCP_AUTH_SOURCE`, `HERMES_CONFIG_PATH`, `OPENCLAW_CONFIG_PATH`, `OPENCLAW_INCLUDE_ROOTS` | обход той конфигурации, которую читает сам демон |
| Транспорт периметра | `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`, `ALL_PROXY`, `REQUESTS_CA_BUNDLE`, `SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS` | политика машины; иначе один агент тихо отцепится от прокси периметра |
| Загрузчик и интерпретаторы | `LD_PRELOAD`, `LD_AUDIT`, `LD_LIBRARY_PATH`, `LD_BIND_NOW`, `DYLD_INSERT_LIBRARIES`, `DYLD_LIBRARY_PATH`, `DYLD_FRAMEWORK_PATH`, `DYLD_FALLBACK_LIBRARY_PATH`, `NODE_OPTIONS`, `BASH_ENV`, `ENV`, `PYTHONSTARTUP`, `PYTHONPATH`, `PERL5OPT`, `RUBYOPT`, `GIT_SSH_COMMAND`, `GIT_SSH`, `GIT_EXTERNAL_DIFF`, `GIT_PAGER`, `GIT_CONFIG_GLOBAL` | каждый из них означает «выполни этот код в процессе агента» — произвольное исполнение, записанное как пара «ключ — значение» |
| Базовые адреса провайдеров | `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_URL`, `OPENAI_BASE_URL`, `OPENAI_API_BASE` | направляют API-ключ CLI на чужой эндпоинт: ключ утекает первым же запросом, а вместе с ним промпты и прочитанные файлы |

Сравнение регистронезависимое, поэтому `ld_preload` и `LD_PRELOAD` блокируются одинаково.

**Что остаётся разрешённым — сознательно.** Ключи провайдера (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`), `HERMES_HOME`, любые прикладные переменные агента. В этом и смысл `custom_env`: запрещены не секреты, а *назначение* и *загрузчик*.

**`custom_args` — та же поверхность.** Флаг, которым CLI можно подсунуть собственный файл настроек, обходит этот список целиком: например, документ настроек одного из CLI несёт и `env`, и `hooks` (shell-команды вокруг вызовов инструментов). Поэтому `--settings` отфильтровывается из `custom_args` **всегда**, а не только когда демон пишет собственный управляемый файл (списки `*BlockedArgs` в `server/pkg/agent/*.go`).

**Чего этот слой не делает.** Он не очищает окружение самого демона. Дочерний процесс по-прежнему видит всё, что видел демон, включая учётные данные провайдера: иначе CLI просто не сможет работать. Уменьшать эту поверхность нужно не списком запретов, а [выделенным пользователем ОС](#operator-checklist) с чистым окружением.

## MCP: конфигурация и недоверенные результаты [#mcp]

### Allowlist [#mcp-allowlist]

`GOOSAR_MCP_ALLOWED_HOSTS` и `GOOSAR_MCP_ALLOWED_COMMANDS` применяются в трёх местах: при записи `mcp_config`, при выдаче задачи демону (claim) и **на самой машине**, в момент слияния конфигураций. Порядок слияния: политика развёртывания, затем библиотека рабочего пространства, затем оверлей задачи, затем локальные серверы машины (пользовательские файлы MCP-конфигурации самих CLI и `.mcp.json` репозитория). Перепроверяется именно локальный слой; отброшенные записи логируются по имени и видны администратору как `blocked: <name> (source local)`. Раньше allowlist был контролем только на записи, и любой пользователь обходил его строкой `mcp-remote https://anything` в собственной конфигурации.

Границы этого слоя, чтобы allowlist не выглядел полнее, чем он есть:

- демон знает расположение локальной MCP-конфигурации **семи из 18** провайдеров. Для остальных он не может прочитать, а значит и отфильтровать то, что CLI наследует нативно. При активной политике такой запуск пишет в лог `deployment MCP allowlist is not enforced on runtime-local servers for this provider`. Закрывается только добавлением раскладки конкретного провайдера;
- у одной из сред выполнения слой держится не только слиянием: при наличии управляемого документа демон передаёт `--strict-mcp-config`, и проектный `.mcp.json` в рабочем каталоге не читается вовсе;
- `custom_args` — такая же доступная другому человеку конфигурация, как `custom_env`, поэтому флаги, которыми можно подменить MCP-конфигурацию или окружение (например, `--mcp-config`, `--settings`, `-c mcp_servers.*` при управляемой конфигурации), отфильтровываются в `server/pkg/agent/*.go`.

### Учётные данные [#mcp-credentials]

Shared-сервер библиотеки — это определение, а не секрет. Запуск собирается на учётных данных того, **за кого** он идёт (инициатора задачи), а не владельца агента. Кто своих значений не завёл, тот сервер не получает вовсе. Подробности — в разделе о библиотеке MCP («The shared MCP library») в `SELF_HOSTING.md`.

Две оговорки, обе приняты сознательно:

- пользовательский слой накладывает значения по `credential_schema` сервера. Shared-определение **без схемы**, в конфигурации которого автор библиотеки вписал токен руками, по-прежнему уезжает всем, кому назначено: схемы нет, накладывать нечего. Секрет в определении без схемы нужно считать общим для всех, кому этот сервер назначен;
- **оверлей Composio — исключение по решению продукта.** Он собирается на подключениях **владельца агента**, а не инициатора, потому что владелец делится этими приложениями как возможностью агента. Интерфейс предупреждает об этом владельца.

### Результаты инструментов недоверенные [#untrusted-tool-results]

Ответ MCP-инструмента — это текст, который написала третья сторона: описание в Jira, письмо, страница вики, скачанная веб-страница. Демон помечает его в транскрипте ограждением `<untrusted-mcp-tool-result>` (`server/internal/daemon/untrusted_tool_result.go`). Полезная нагрузка экранируется, поэтому закрыть ограждение изнутри нельзя ни в каком регистре.

Границы этой пометки нужно понимать точно:

- это **советующий признак происхождения, а не граница безопасности**. Он говорит послушной модели «это данные», но не делает модель неспособной выполнить инструкцию, вписанную в эти данные;
- демон помечает **только копию в транскрипте**. Сам CLI разговаривает с MCP-сервером напрямую, и байты, которые модель прочитала во время выполнения, через эту функцию не проходили и пройти не могут. Выигрыш — на следующем шаге: сводка, handoff-заметка, промпт следующей задачи, собранный из этого транскрипта, а также человек, который читает прогон и видит происхождение текста;
- встроенные инструменты (`Read`, `Bash` и другие) не оборачиваются: это собственная работа агента на машине, а не данные третьей стороны.

**Позиция по prompt injection в целом.** Всякий результат инструмента и всякий текст из внешней системы — недоверенные данные. Это относится к тексту issue и комментариев (в том числе пришедших вебхуком), к handoff-заметкам, к результатам MCP. Разметка от них не защищает. Защищают классы риска L0–L4: необратимые операции проходят через явное подтверждение человека, административные маршруты закрыты `RequireHumanActor`. Не добавляйте возможность, единственной защитой которой служит то, что её вход приехал внутри ограждения.

## Что обеспечивает Goosar, а что — оператор [#who-provides-what]

| | Обеспечивает Goosar | Обеспечивают ОС и оператор |
|---|---|---|
| Файловая система | отказ от запуска вне `GOOSAR_ALLOWED_WORKDIR_ROOTS` | всё остальное: права, отдельный пользователь, песочница провайдера, отсутствие общего `$HOME` |
| Сеть | allowlist хостов и команд MCP (конфигурация) | сетевой фильтр, прокси периметра, DNS |
| Окружение | список запретов для загрузчика, базовых адресов и политики машины | чистое окружение процесса демона |
| Секреты | шифрование в БД (`GOOSAR_MCP_SECRET_KEY`), пользовательские учётные данные | keychain и агент SSH вне доступа этого пользователя |
| Действия в Goosar | роли, членство в рабочем пространстве, `RequireHumanActor`, классы риска | — |
| Изоляция процесса | **ничего** | **всё** |

## Что должен сделать оператор [#operator-checklist]

Минимум для установки, где важна изоляция:

1. **Выделенный пользователь ОС для демона.** Не учётная запись сотрудника. Без SSH-ключей, без билета Kerberos, без сессий облачных CLI, без доступа к общим ресурсам, которых задача не должна касаться.
2. **Отдельный `$HOME`.** Общий домашний каталог с человеком сводит на нет пункт 1 и, кроме того, отдаёт задаче локальные MCP-серверы этого человека.
3. **Профиль песочницы**, если платформа его даёт: seccomp или AppArmor в Linux, Seatbelt (`sandbox-exec`) в macOS, контейнер с примонтированным только рабочим каталогом. Собственной песочницы Goosar не ставит.
4. **`GOOSAR_ALLOWED_WORKDIR_ROOTS`** — задать явно.
5. **Сетевой фильтр на исходящие соединения** от пользователя демона. Allowlist MCP — контроль конфигурации, а не egress-фильтр.
6. **`permission_mode=private` по умолчанию** на профиле периметра: агент откликается только тому, кто им владеет, пока владелец не решил иначе.
7. **Ротация ключей и резервные копии** по процедурам из `SELF_HOSTING.md`, разделы «Резервное копирование и восстановление» (Backup and Restore) и «Ротация ключей шифрования» (Rotating an encryption key). Дамп БД равносилен хранилищу секретов.

## Принятый остаточный риск [#accepted-residual-risk]

Записан здесь, чтобы ИБ-ревью видело его как решение, а не как находку:

- агент действует правами владельца среды выполнения, включая MCP; сервисные аккаунты для общего доступа — обязанность заказчика;
- CLI провайдеров работают с отключёнными подтверждениями; безопасность держится на классах риска Goosar, а не на диалогах CLI;
- разметка недоверенных данных — сигнал происхождения, а не защита от prompt injection;
- корни запуска и список запрещённых переменных ограничивают конфигурацию, а не уже запущенный процесс;
- allowlist MCP на локальном слое покрывает семь провайдеров из восемнадцати; для остальных остаётся нативное наследование (в логе появляется предупреждение);
- shared MCP-сервер без `credential_schema` с секретом, зашитым в определение, — общий секрет для всех, кому он назначен;
- оверлей Composio работает от имени владельца агента, а не инициатора задачи;
- демон под выделенным низкопривилегированным пользователем «из коробки» — задача за пределами 1.0.
