**Среда выполнения** в Goosar — это демон на вашей машине в паре с одним внешним CLI, который демон нашёл в `PATH`. Именно на такой машине агенты выполняют задачи. Найденные среды выполнения показываются на шаге онбординга «Подключить среду выполнения» и на странице «Среды выполнения». Пока ни одной нет, агенты остаются офлайн.

Поддерживаемые раннеры в интерфейсе, CLI и документации обозначаются нейтральными кодами `runtime-a` … `runtime-r` и названиями вида «Runtime A». Реальные имена внешних CLI и моделей хранит реестр раннеров и конфигурация вашего развёртывания. Если нужного инструмента среди поддерживаемых нет, [добавьте пользовательскую среду выполнения](/custom-runtimes).

<Callout type="info">
Сервер Goosar никогда не видит ни ваших API-ключей, ни самих инструментов. Установка, аутентификация и доступ к моделям живут на вашей локальной машине. Если что-то не работает, проблема почти всегда локальная.
</Callout>

## Перед началом [#before-you-start]

Два требования действуют для любого раннера:

1. **Демон Goosar должен быть запущен.** Выполните `goosar daemon start` после установки CLI Goosar (его отдаёт само развёртывание, см. [быстрый старт self-host](/self-host-quickstart)) либо используйте десктопное приложение, которое запускает демон автоматически. Без работающего демона обнаруживать раннеры некому.
2. **Бинарник раннера должен быть доступен в `PATH`.** Демон вызывает его по имени, которое задаёт поле `cliName` записи раннера в реестре. Если `which <имя>` не находит бинарник в вашем терминале, демон его тоже не найдёт.

После установки или изменения `PATH` перезапустите демон:

```bash
goosar daemon restart
```

Либо перезапустите десктопное приложение. Демон пересканирует `PATH` при каждом старте.

## Какие среды выполнения поддерживаются [#supported-runtimes]

Список поддерживаемых раннеров задаёт реестр. Каждая запись содержит:

| Поле | Что означает |
|---|---|
| `code` | Нейтральный код `runtime-a` … `runtime-r`, который используется в API и интерфейсе. |
| `displayName` | Отображаемое имя вида «Runtime A». |
| `cliName` | Имя бинарника, которое демон ищет в `PATH`. |

Реестр лежит в исходниках сервера, в файле `server/pkg/agent/runtimeregistry/runtimes.yaml`. Для установленного развёртывания сопоставление кода и имени бинарника вам сообщает администратор.

Чтобы увидеть, какие среды выполнения уже зарегистрированы в рабочем пространстве, выполните:

```bash
goosar runtime list
```

Команда выводит таблицу со столбцами `ID`, `NAME`, `MODE`, `PROVIDER`, `STATUS` и `LAST_SEEN`. Флаг `--output json` даёт тот же список в JSON. Какие раннеры демон нашёл на этой машине, показывает строка `Agents` в выводе `goosar daemon status`.

## Установка раннера вместе с CLI [#installing-the-runner]

Установщик по умолчанию ставит только CLI `goosar`: раннер не скачивается и не устанавливается, пока вы его не выберете. Выбрать раннер можно флагом `--runner <имя>` или переменной `GOOSAR_RUNNER`:

```bash
curl -fsSL <app-url>/install.sh | bash -s -- \
  --app-url <app-url> \
  --server-url <server-url> \
  --runner <имя>
```

Допустимые значения выводит `install.sh --help`; `none` означает «без раннера» и действует по умолчанию. В интерактивном запуске без флага установщик спрашивает один раз, в неинтерактивном (`curl | bash` в CI) раннер не ставится. Псевдонимы `--with-agent` и `--without-agent` выбирают раннер, входящий в развёртывание, и `none` соответственно. В десктопном приложении раннер тоже ставится только по вашему выбору в настройках демона.

Установщик для Windows (`install.ps1`) принимает только `-Runner none`: у раннера из развёртывания нет сборки под Windows. Если раннер вы ставите сами, установите его по инструкции его поставщика и убедитесь, что бинарник попал в `PATH`.

Проверить машину до запуска демона можно командой `goosar doctor`. Она локально проверяет наличие `goosar` в `PATH`, agent CLI, Node/npm, git и других зависимостей и печатает, чего не хватает. Сам раннер она не запускает, только проверяет исполняемый файл и его `--version`.

## Аутентификация и доступ к моделям [#authentication]

Вход в раннер, ключи и подписки настраиваются на вашей машине средствами самого раннера, по его документации. Goosar не передаёт эти данные на сервер и не хранит их. Доступ к моделям определяется вашей учётной записью у поставщика раннера, а не настройками Goosar. Если раннер найден, но задачи завершаются ошибкой аутентификации, войдите в него в обычном терминале под тем же пользователем, от имени которого работает демон.

## После установки [#after-installing]

1. Перезапустите демон: `goosar daemon restart` (или десктопное приложение).
2. Выполните `goosar daemon status`. В выводе должна быть строка `running`, а в строке `Agents` — код найденной среды выполнения.
3. Откройте страницу «Среды выполнения» или вернитесь на шаг онбординга «Подключить среду выполнения». Среда должна появиться через несколько секунд.
4. Выполните `goosar runtime list` и убедитесь, что у нужной среды выполнения статус онлайн.

После этого можно создать агента и назначить ему первую задачу.

## Если среда выполнения не появилась [#troubleshooting]

**Раннер не найден в `PATH`.** Десктопное приложение и демон, запущенный из него, не наследуют `PATH` вашего терминала: на macOS и Linux графическая сессия получает урезанный `PATH`. Проверьте, что `which <имя>` находит бинарник в терминале, затем перезапустите демон. Для пользовательской среды выполнения абсолютный путь можно закрепить на этом компьютере командой `goosar runtime profile set-path`, подробности на странице [Пользовательские среды выполнения](/custom-runtimes#command-not-found).

**Демон не запущен.** Выполните `goosar daemon status`. Если демон не работает, запустите его через `goosar daemon start` и посмотрите журнал: `goosar daemon logs`.

**Среда выполнения не появилась после установки.** Перезапустите демон (`goosar daemon restart`), чтобы он заново просканировал `PATH`. Проверьте, что имя бинарника в `PATH` совпадает со значением `cliName` из реестра, а не с другим названием продукта. Затем запустите `goosar doctor` и посмотрите, что он считает отсутствующим.

**Среда выполнения есть, но офлайн или задачи падают.** Проверьте статус в `goosar runtime list`, журнал демона и вход в сам раннер (см. раздел про аутентификацию выше).
