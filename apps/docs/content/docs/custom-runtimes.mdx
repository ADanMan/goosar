Профиль пользовательской среды выполнения позволяет рабочему пространству подключить ИИ-инструмент, который использует один из поддерживаемых Goosar протоколов, но запускается командой, принятой в вашей команде: например, через обёртку, подставляющую учётные данные. В интерфейсе такие профили лежат в разделе «Свои среды выполнения» на странице **Среды выполнения**.

Профиль общий для всего рабочего пространства. Каждый компьютер с демоном регистрирует среду выполнения, только если нужная команда на нём действительно есть. Базовое семейство протоколов задаётся при создании и потом не меняется. Пока среду выполнения используют агенты, удалить профиль нельзя.

Список поддерживаемых инструментов и способы их установки — на странице [Установка среды выполнения для агента](/install-agent-runtime).

## Команда и аргументы [#command-and-arguments]

В поле «Команда» вставьте ту же строку, что вы запускаете в терминале:

```sh
agent --model composer-2.5
```

Goosar сохранит её как два поля:

- `command_name`: `agent`
- `fixed_args`: `["--model", "composer-2.5"]`

Демон запускает процесс напрямую, как `exec.Command(command_name, fixed_args...)`. Оболочка (shell) не используется.

Поддерживается:

- аргументы, разделённые пробелами;
- одинарные и двойные кавычки для значений с пробелами;
- обратный слеш для литерального пробела или кавычки.

Разбор строки в интерфейсе рассчитан на argv, это не полноценный POSIX shell. Внутри двойных кавычек `\` экранирует следующий символ как есть; если `$` или обратные апострофы должны остаться буквальными, используйте одинарные кавычки.

Не поддерживается:

- конвейеры, перенаправления, `;`, `&&`, `||`;
- обратные апострофы;
- подстановка `$VAR` и `$(...)`.

Если среде выполнения нужно поведение shell, напишите скрипт-обёртку и укажите его в качестве команды.

<Callout type="info">
Уже запущенные задачи сохраняют аргументы, с которыми стартовали. Изменения команды или аргументов профиля применяются к новым задачам после того, как демон заново зарегистрируется.
</Callout>

## Управление из CLI [#cli]

Профилями можно управлять командой `goosar runtime profile`:

| Команда | Что делает |
|---|---|
| `list` | Показывает профили рабочего пространства (`--output table` или `json`). |
| `create` | Создаёт профиль: `--protocol-family`, `--command-name`, `--display-name` обязательны, `--description` необязателен. |
| `update <profile-id>` | Меняет название, команду, описание или включает и отключает профиль (`--enabled`). Семейство протоколов изменить нельзя. |
| `delete <profile-id>` | Удаляет профиль. |
| `set-path <profile-id> --path <путь>` | Закрепляет абсолютный путь к исполняемому файлу на этом компьютере. |
| `unset-path <profile-id>` | Снимает закрепление пути. |

Допустимые значения `--protocol-family` CLI проверяет заранее и при опечатке выводит полный список. Аргументы команды (`fixed_args`) в CLI не задаются: их разбирает форма в интерфейсе.

## Команда не найдена [#command-not-found]

Демон, запущенный из десктопного приложения, может получить другой `PATH`, чем ваш интерактивный терминал. Если у пользовательской среды выполнения показана ошибка регистрации, хотя команда в терминале работает, закрепите абсолютный путь на этом компьютере:

```sh
goosar runtime profile set-path <profile-id> --path /home/u/bin/agent
```

Путь должен быть абсолютным. Он записывается в локальную конфигурацию CLI и никогда не отправляется на сервер. После этого перезапустите демон, чтобы он заново зарегистрировал профиль:

```sh
goosar daemon restart
```

Снять закрепление можно командой `goosar runtime profile unset-path <profile-id>`; демон тоже нужно перезапустить.

## Порядок обновления [#upgrade-order]

Аргументы пользовательских сред выполнения и отчёты об ошибках регистрации требуют версий сервера и демона, которые поддерживают запуск с `fixed_args` и отчёты `failed_profiles`. При смешанном развёртывании сначала обновите сервер, затем раскатывайте новые демоны. Тогда профили, которые не удалось зарегистрировать, будут записаны, а не отклонены как пустая регистрация среды выполнения.
