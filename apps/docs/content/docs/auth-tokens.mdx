В Goosar три вида токенов, по одному на каждый контекст: браузерный веб-интерфейс, командная строка со скриптами и демон. Все они действуют от вашего имени, но различаются областью доступа и сроком жизни.

## Три токена [#the-three-tokens]

| Токен | Формат | Где используется | Срок жизни |
|---|---|---|---|
| **Cookie с JWT** | HttpOnly-cookie `goosar_auth` | Браузер | 30 дней по умолчанию (переменная `AUTH_TOKEN_TTL`) |
| **Персональный токен доступа (PAT)** | Префикс `gsl_` | CLI, скрипты, прямые вызовы API | Без срока по умолчанию; при создании можно выбрать срок: 30 дней, 90 дней, 1 год (в API — поле `expires_in_days`) |
| **Токен демона** | Префикс `mdt_` | Связь демона с сервером | Управляется самим демоном |

В повседневной работе вы напрямую имеете дело только с первыми двумя. Токен демона выдаётся и используется демоном автоматически.

## К чему имеет доступ каждый токен [#what-each-token-can-hit]

| Маршрут API | Cookie с JWT | PAT | Токен демона |
|---|---|---|---|
| `/api/user/*` (действия на уровне пользователя) | да | да | нет |
| `/api/workspaces/:id/*` (уровень рабочего пространства) | да | да | нет |
| `/api/daemon/*` (только для демона) | нет | да (для обратной совместимости) | да |
| WebSocket `/ws` (уведомления в реальном времени) | да (cookie) | да | нет |

**PAT открывает почти всё**, потому что представляет «вас целиком». Токен демона позволяет только то, что нужно демону: получать задачи и отправлять результаты.

**К `/api/daemon/*` можно обратиться и с PAT, но область доступа различается.** PAT представляет **пользователя целиком**: после аутентификации он видит все рабочие пространства, в которых вы состоите. Токен демона привязан при создании к одному рабочему пространству и работает только с его ресурсами. В production запускайте демон с токеном демона; PAT для этого использовать не стоит, иначе вы выдадите демону куда больше прав, чем ему нужно.

## Вход [#logging-in]

### Почта и код подтверждения [#email-and-verification-code]

1. Введите почту; сервер отправит 6-значный код.
2. Введите код; сервер выдаст cookie с JWT (в браузере) или обменяет его на PAT (в CLI).

Если в развёртывании включён корпоративный вход (OIDC или LDAP), способ входа зависит от настройки `GOOSAR_AUTH_METHODS`; подробнее в разделе [Настройка входа и регистрации](/auth-setup#corporate-sign-in). Личный второй фактор (TOTP) включается в разделе «Безопасность» настроек аккаунта. К PAT он не применяется.

<Callout type="warning">
**Операторам самостоятельного размещения.** Оставляйте `GOOSAR_DEV_VERIFICATION_CODE` пустой на любом развёртывании, доступном из сети. Если включить фиксированный тестовый код, любой, кто может запросить код, войдёт с этим значением, пока `APP_ENV` не production. См. [Настройка входа и регистрации](/auth-setup).
</Callout>

## Создание, просмотр и отзыв PAT [#creating-viewing-and-revoking-a-pat]

**Создать** PAT можно двумя способами:

- **Веб-интерфейс**: Настройки → API-токены → поле названия и кнопка «Создать»
- **CLI**: `goosar login` создаёт токен автоматически, если локального PAT ещё нет; готовый токен можно передать через `goosar login --token`

<Callout type="warning">
**Полный PAT показывается один раз, в момент создания.** После обновления страницы или закрытия диалога увидеть его снова нельзя.

Goosar хранит в базе данных только хеш PAT, поэтому даже сервер не может восстановить исходное значение. Скопируйте и сохраните токен сразу. Если он потерян, остаётся только отозвать его и создать новый.
</Callout>

**Просмотр** существующих PAT (название, время создания и последнего использования, но **не** сам токен) находится в Настройки → API-токены.

**Отзыв**: нажмите «Отозвать» в списке. Отзыв действует сразу: следующий запрос с этим PAT будет отклонён с ответом 401.

## Выход удаляет только локальный токен [#logging-out-only-deletes-the-local-token]

Когда вы выполняете `goosar auth logout` или нажимаете «Выйти» в веб-интерфейсе:

- **Локальный токен удаляется**: CLI убирает PAT из `~/.goosar/config.json`, браузер удаляет cookie.
- **На сервере PAT остаётся действующим**: если кто-то успел получить ваш PAT до выхода (например, скопировал его на другую машину), он **по-прежнему может им пользоваться**.

<Callout type="warning">
**Если вы подозреваете утечку PAT, одного выхода недостаточно.** Откройте Настройки → API-токены и **отзовите** токен. Только отзыв немедленно лишает силы утёкший токен.
</Callout>
